Database structure and implemented recruitment workflows

8 diagrams · Offline SVG · Editable sources
Crow’s Foot ER: PK = primary key, FK = foreign key, UK = unique. One = ||, zero or one = circle + bar, zero or many = circle + crow's foot. Chen ER: rectangles = entities, diamonds = relationships, ovals = attributes, underlined labels = keys; (min,max) pairs describe the adjacent entity’s participation. UML multiplicities: 1, 0..1 and 0..*.
ER / Crow’s Foot notation

Relational overview — Crow’s Foot ER

All 12 tables and all 16 foreign keys, with identity fields only.

100%

Reading this diagram

  • Use the Domain selector to view one area at a time. Reference labels repeat an existing entity; all relationships appear once across the three views.
  • Notation used: Crow’s Foot ER. Table rectangles contain attributes; endpoint markers express cardinalities.
  • Crow's-foot markers show cardinalities at both ends. Dashed links are non-identifying: every child table has its own surrogate primary key.
  • A user may have zero or one student profile and zero or one recruiter profile. Role exclusivity is application logic, not a database inheritance relationship.
  • The two messages-to-users links are distinct: sender_id and receiver_id.

Reading this diagram

  • Only recruiter_id on internships and internship_id on interviews are nullable foreign keys.

ER / Chen notation

Conceptual entities and relationships — Chen ER

Rectangles, diamonds and attribute ovals, with explicit (min,max) participation.

100%

Reading this diagram

  • Use the Domain selector to view one area at a time. Reference labels repeat an existing entity; all relationships appear once across the three views.
  • Chen shapes: rectangle = entity, diamond = relationship, oval = attribute. Underlined id is a primary key.
  • This view uses the (min,max) participation variant: read a pair beside an entity as how many relationship instances that entity can participate in. (0,N) means optional many; (1,1) means exactly one; (0,1) means optional one.
  • Example: STUDENTS (0,N) — Submits — (1,1) APPLICATIONS. A student can submit many applications; each application belongs to exactly one student. These same-side pairs differ from where Crow’s Foot endpoint markers are read.
  • Only selected non-FK attributes are shown. Foreign keys are expressed as relationships; the full Crow’s Foot view retains every mapped field.
  • All mapped entities have their own primary key, so no weak entity, identifying diamond, derived attribute or multivalued attribute is invented. Reference labels repeat the same entity across focused views.
  • Notation references: Emory CS457 ER diagrams and University of Pittsburgh ER model notes (min,max participation).
